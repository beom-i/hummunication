# 설교·사진 편집 데이터

이번 화면은 기존 `/weekly?step=2` 안에서 `view=sermon`(기본 정보·표지) → `view=sermon-preview`(정리 내용·본문 카드)로 이동한다. 기본 정보는 표지에 즉시 반영한다. 본문 화면의 앨범형·목록형은 같은 페이지들을 보여 주며 카드 클릭으로 확대한다.

## 설교

원본은 `sermon.document`의 Tiptap JSON 하나다. 날짜·설교자·제목·본문 구절은 기존 필드에 저장한다. 허용 문서는 문단·줄바꿈·텍스트이며, 서식은 bold/italic/underline/strike와 textStyle의 color/fontSize다. 글자 크기는 8~32 논리 px, 색상은 6자리 HEX로 검증한다. UI에는 기본 10색과 HEX 입력, 글자 크기 선택을 제공한다.

```json
{
  "date": "2026-11-08",
  "speaker": "담당 목사님",
  "title": "설교 제목",
  "passage": "본문 구절",
  "document": {
    "type": "doc",
    "content": [{ "type": "paragraph", "content": [{
      "type": "text", "text": "강조한 문장",
      "marks": [{ "type": "bold" }, { "type": "textStyle", "attrs": { "color": "#B92330", "fontSize": "18px" } }]
    }] }]
  }
}
```

Enter는 문단을 나눈다. 빈 문단·줄바꿈도 높이를 차지한다. 사용자는 Enter로 위치를 조절하고, 높이가 넘치면 본문 페이지가 자동 추가된다. 별도의 강제 페이지 구분자나 특수 단축키는 없다. 고정 7장·문장 반복·내용 잘라내기는 사용하지 않는다.

출력은 480×600 논리 캔버스, 본문 폭 403.2px·높이 464px다. 같은 HTML/CSS와 로드된 폰트로 높이를 측정하고 미리보기·확대·1200×1500 PNG/JPG를 만든다. 긴 문단이 나뉘어도 인라인 서식과 모든 글자를 유지한다. HTML은 검증한 문서를 허용 태그로 직렬화하며 텍스트는 이스케이프한다. 사용자 HTML·임의 CSS는 저장·삽입하지 않는다. HTML과 분할 결과는 파생 값이며 별도 편집 원본이 아니다.

기존 로컬 드래프트의 `sermon.content` 문자열은 줄바꿈을 보존한 문단으로 변환한다. 임시저장 때 JSON을 저장하며 복원 실패 시 원본을 지우지 않는다.

## 사진

사진은 클릭하면 재편집 모달을 연다. 비율은 실제 카드의 사진 슬롯과 같은 119:71이다. 이동·확대/축소·좌우 90도 회전 후 적용하거나 취소한다. 원본 사진은 수정하지 않는다.

```json
{
  "photoEdit": {
    "rotation": 90,
    "sourceWidth": 1200,
    "sourceHeight": 800,
    "crop": { "x": 0.05, "y": 0.2, "width": 0.9, "height": 0.358 }
  }
}
```

`crop`은 회전한 이미지의 바운딩 박스 기준 0~1 좌표다. 원본 크기·회전·영역으로 다시 같은 결과를 만들며 확대 배율을 중복 저장하지 않는다. 업로드 미리보기·순 목록·결과 카드·다운로드에 같은 영역을 사용한다. 교체/삭제 시 이전 크롭 정보도 비운다.

현재 목업은 원본을 `photo`의 Data URL로 보존한다. DB 연결 때는 기존 DB 초안의 `media_assets` 원본 ID로 바꾸고 이 편집 정보는 `family_groups` 안에 보관하면 된다. 크롭 전용 테이블은 필요하지 않다. 사진 접근은 같은 팀의 원본인지 서버에서도 검증해야 한다.

DB 마이그레이션·원격 적용·실제 업로드 API는 이번 UI 변경에 포함하지 않는다. 운영 저장/생성 API를 연결할 때도 같은 문서·사진 스키마로 서버 입력을 다시 검증한다.
