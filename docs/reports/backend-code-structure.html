    SAVE VS COMPLETE

    미완성 저장과 다음 단계를 나눕니다

    • 저장: 빈 입력을 허용하고 타입·길이·날짜 형식·허용 서식을 검증합니다. 같은 저장 스키마를 프론트와 서버가 사용합니다.
    • 다음·출력: 선택한 콘텐츠에 한해 필수 값·본문 내용·사진 편집 유효성을 추가 검사합니다.
    • 서버: 클라이언트 검증과 무관하게 다시 검사합니다. 일반 Data API 쓰기 권한으로 DB 함수의 검증을 우회하지 못하도록 합니다.
    • 타입: DB 일반 속성은 Supabase 생성 타입, 폼 입력은 Zod 추론, Tiptap·groups JSON 내부도 Zod로 검증합니다.
    SOFT DELETE

    삭제는 deleted_at 하나로 통일합니다

    • weekly / sermon / family / files에 deleted_at timestamptz NULL. sender에도 같은 규칙을 적용합니다.
    • 일반 조회와 RLS는 활성 행만 반환합니다. 삭제 시 수정자·시각을 기록합니다.
    • 주보 삭제는 연결 원본을 남깁니다. 삭제된 주보가 참조하는 원본도 연결 해제 전에는 삭제할 수 없습니다.
    • 활성 주보 날짜만 부분 UNIQUE입니다. 새 주보는 새 콘텐츠 ID를 사용합니다.
    • 사진은 모든 문답 참조를 확인하고 메타데이터만 숨깁니다. Storage 원본은 즉시 지우지 않습니다.
